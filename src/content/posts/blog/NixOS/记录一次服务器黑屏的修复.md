### 问题症状

开机后 systemd 的 log 输出相当一部分后，控制台直接黑掉。盲打可以有反应，但没有任何显示输出。

系统为 NixOS unstable, 大致在 26.05 版本。没有开启桌面环境。  
硬件配置如下：  
	CPU Ryzen 7 3800X
	显卡 Radeon RX 550

### 解决过程

首先尝试回滚 generation，但哪怕是之前用着完全没问题的 generation 也会有这个 bug. 因此思考是不是硬件问题。尝试拔插内存和显卡，但无效。使用 memtest86+ 检查内存，没有查出问题。

	这里顺便记录一下怎么在 NixOS 里用 memtest86+
	在 `configuration.nix` 里加入 `boot.loader.systemd-boot.memtest86.enable = true;`
	之后就可以在 boot 时选取进入 memtest86+. 会自动开始内存检测。

在 GPT 5.6-Sol 的帮助下，发现启用内核启动参数 `nomodeset` 可以正确进入 tty. 这个参数会禁用 GPU KMS.

在启用这个参数作为临时解决方案后，GPT 5.6-Sol ssh 至服务器检查了各项数据，发现 RX 550 的识别没有问题，HDMI 状态、EDID 等各项数据也全都正常，说明显卡没有问题。

最初怀疑是 console blank 导致 tty 假死，但设置内核启动参数 `consoleblank=0` 并没有解决问题，说明也不是控制台超时熄屏的问题。

最后在 GPT 5.6-Sol 的建议下尝试t通过 `video=HDMI-A-1:1920x1080@60` 显式指定显示模式到 1920x1080@60，成功解决问题。  
由于 RX 550 不支持 4K60 输出，而显示屏是支持 4K60 的，应当是内核错误自动选择了 4K60 的显示模式，导致 RX 550 过载了。

这里的 `HDMI-A-1` 是显卡的连接器名，可以通过 `ls /sys/class/drm` 查看。显示的结果应当类似于
```bash
ls /sys/class/drm  
card1  card1-DP-1  card1-DVI-D-1  card1-HDMI-A-1  renderD128  version
```

这里的 `card1` 是设备编号，后面的 `HDMI-A-1` 等是内核接受的 connector 名。可以通过 `cat /sys/class/drm/card1-HDMI-A-1/status` 来找到状态为 connected 的连接器。

此前的 generation 没有问题可能是因为存留的 generations 并不包含真正可行的版本；又或者是 EDID 协商结果不一致存留在了配置里，内核更新使配置更新导致默认结果变成了 4K60.

	这里也记录一下如何临时增改内核参数。
	在 boot 时的 generation 选取页面选中一个 generation, 按下 e 会出现内核参数列表，在其末尾添加如 `nomodeset` 或 `video=HDMI-A-1:1920x1080@60` 等字段即可。

### 解决方案

手动设置显示模式到 1080P60 或 4K30.

可以在 `configuration.nix` 里增加
```nix
boot.kernelParams = [
  "video=HDMI-A-1:1920x1080@60"
];
```
